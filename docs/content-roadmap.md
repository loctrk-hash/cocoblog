# 內容路線圖

> 最後更新：2026-11-13
> 搭配 `docs/handover.md` 使用。這份文件是發文進度的唯一依據：**每發布一篇就更新狀態**，換 session 才不會重複寫或漏寫。

---

## 1. 目標

- 累積 **15–20 篇**有實質內容的原創文章，作為 Google AdSense 主網域審核的內容基礎。
- 三個分類維持主題一致性，讓 Google 與讀者都清楚這個網站是「記帳理財 + App 教學」。

| 分類 | 規劃篇數 | 定位 |
|---|---|---|
| `記帳技巧` | 7 | 實際操作面：怎麼記、怎麼分類、怎麼回顧 |
| `理財觀念` | 7 | 基礎觀念：預備金、儲蓄率、現金流、順序 |
| `App 教學` | 11 | CocoBook 記帳工具的實際操作與報表解讀；**全部需要素材與 review** |

規劃合計 **25 篇**（已完成 3 篇）。25 篇是清單上限，不是送審門檻；非 App 的 14 篇完成後，再加 6 篇 App 教學就達到 20 篇。App 教學不列入「可自行發布」的範圍。

## 5. 每篇的撰寫規格

- **長度**：1,800–3,000 字（中文）。短於 1,500 字容易顯得單薄。
- **結構**：
  - 導言 2–4 段（痛點 → 這篇會談什麼 → 讀者能得到什麼）
  - `<!--more-->`
  - 3–6 個 `##` 小標
  - 至少一個具體例子或數字試算
  - 結尾給「今天就能做的一件事」
- **原創性**：加入自己的經驗、判斷與取捨，不要只是名詞解釋。AdSense 會抓低價值內容。
- **內部連結**：每篇至少連到 1–2 篇站內其他文章（例如記帳技巧連到 `first-month-budgeting`）。
- **description**：60–120 字，直接寫這篇的價值，不要寫成標題重複。
- **tags**：2–4 個，盡量重用既有標籤，避免產生大量只有一篇的標籤頁。
- **不要**：不要寫投資標的推薦、保證收益、醫療或法律建議；不要放與主題無關的內容。
- **App 教學**：只寫實際存在的功能；截圖上的數字可以是示範資料，但要說明是示範。

### App 教學發布前置規則

```text
1. 使用者通知要寫某一篇，並提供截圖／畫面與意見
2. agent 依實際功能調整該篇大綱（只改大綱，不直接寫全文）
3. 使用者 review 大綱
4. 使用者明確說「可以發布」
5. agent 才寫全文 → 本機驗證 → 部署 → commit
```

沒有第 4 步的明確同意，App 教學一律不部署。大綱調整期間狀態用 `📝`，review 通過後改 `🟡`。

## 6. AdSense 送審檢查清單

### 內容

- [ ] 15–20 篇原創文章，每篇有實質內容與個人觀點
- [ ] 三個分類都有文章，分類頁不是空的
- [ ] 沒有大量重複、空泛或明顯 AI 灌水的段落

### 網站

- [ ] 首頁、文章列表、分類、文章導覽正常
- [ ] 行動版可讀（PaperMod 預設 RWD）
- [ ] `關於` 頁有網站定位與聯絡方式
- [ ] `隱私權政策` 已包含 AdSense / Cookie 說明（已具備）
- [ ] HTTPS 正常、`www` 轉址正常
- [ ] `robots.txt` 沒有誤擋文章
- [ ] `sitemap.xml` 可存取，且已提交 GSC

### 帳號

- [ ] 用要收款的 Google 帳號申請
- [ ] 網站新增 `cocobook.cc`
- [ ] 驗證方式選 `ads.txt`，把 AdSense 給的那一行放到 `static/ads.txt`
- [ ] `./deploy.sh` 後確認 `https://cocobook.cc/ads.txt` 回 200
- [ ] 送審後耐心等 1–4 週，被拒可補內容再送，不會有懲罰

### 通過後

啟用方式已整理在 `docs/handover.md` 第 4 節「廣告版位（`params.ads`）」。摘要：

- [ ] `hugo.toml` 的 `[params.ads]` 設 `enabled = true`
- [ ] 填入 `client`（`ca-pub-...`）與 `articleBottomSlot`
- [ ] 把正式 `ads.txt` 放進 `static/ads.txt`（不要放假檔）
- [ ] `./deploy.sh` 後確認文章頁有 `adsbygoogle`、首頁與 `/sites/` 沒有
- [ ] 用瀏覽器確認廣告載入前後沒有明顯跳版
